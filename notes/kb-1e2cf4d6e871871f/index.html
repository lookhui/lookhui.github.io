# 核心要点

  • Redis is a text based protocol, you can just send the command in a socket and the returned values will be readable. Also remember that Redis can run using ssl/tls (but this is very weird).
  • In this last case, this means that you need valid 凭据 to access the Redis instance.
  • By default Redis can be accessed without 凭据. However, it can be configured to support only 密码，or username + 密码.\
  • It is possible to set a 密码 in redis.conf file with the parameter requirepass or temporary until the service restarts connecting to it and running: config set requirepass p@ss$12E45.\
  • If only 密码 is configured the username used is "default".\
  • Also, note that there is no way to find externally if Redis was configured with only 密码 or username + 密码.
  • In case you found valid 凭据 you need to authenticate the session after establishing the connection with the command:
  • Valid 凭据 will be responded with: +OK
  • redis-rogue-server can automatically get an interactive shell or a 反弹 Shell in Redis (<=5.0.5).
  • This technique is automated here: https://github.com/Avinash-acid/Redis-Server - 利用
  • Attacker can authenticate to Redis and Lua is enabled (EVAL/EVALSHA or FUNCTION are usable)
  • From 利用 to RCE requires memory grooming and native code pivoting beyond the Redis Lua sandbox.
  • CVE-2025-46818 — Cross-user 权限提升 via basic type metatables
  • Root cause: On engine initialization, metatables for basic types (e.g., strings, booleans) weren’t set read-only. Any authenticated user can poison them to inject methods other users might call later.
