# 核心要点

  • PostgreSQL SQL 注入 refers to a type of security 漏洞 where attackers 利用 improperly sanitized user input to execute unauthorized SQL commands within a PostgreSQL database.
  • NOTE: Earlier versions of Postgres did not accept absolute paths in pg read file or pg ls dir. Newer versions (as of 0fdc8495bff02684142a44ab3bc5b18a8ca1863a commit) will allow reading any file/filepath for super users or users in the default role read server files group.
  • Using pg read file, pg ls dir
  • Installations running Postgres 9.3 and above have functionality which allows for the superuser and users with 'pg execute server program' to pipe to and from an external program using COPY.
  • Retrieve all table-level privileges for the current user, excluding tables in system schemas like pg catalog and information schema.
  • This page aims to explain different tricks that could help you to 利用 a SQLinjection found in a postgresql database and to compliment the tricks you can find on https://github.com/swisskyrepo/PayloadsAllTheThings/blob/master/SQL Injection/PostgreSQL Injection.md
  • You can read this example to see a CTF example of how to load data inside large objects and then exfiltrate the content of large objects inside the username of the function dblink connect.

  • Manipulating strings could help you to 绕过 WAFs or other restrictions.\
