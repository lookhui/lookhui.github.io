# 核心要点

  • 远程文件包含 RFI (RFI): The file is loaded from a remote server (Best: You can write the code and the server will execute it). In php this is disabled by default (allow url include).\
  • The 漏洞 occurs when the user can control in some way the file that is going to be load by the server.
  • Vulnerable PHP functions: require, require once, include, include once
  • A interesting tool to 利用 this 漏洞: https://github.com/kurobeats/fimap
  • A list that uses several techniques to find the file /etc/ 密码 (to check if the 漏洞 exists) can be found here
  • A list that uses several techniques to find the file /boot.ini (to check if the 漏洞 exists) can be found here
  • Inline SVG 载荷: TCPDF::startSVGElementHandler () reads the xlink:href attribute from <image> elements before running urldecode (). Embedding a malicious SVG inside a data URI makes many HTML sanitizers ignore the 载荷 while TCPDF still parses it:
  • HTML <img> handler: TCPDF::openHTMLTagHandler () contains the same order-of-operations bug, allowing direct HTML 载荷 such as src="%2f..%252f..%252ftmp%252fsecret.png" to read any locally reachable bitmap.
  • Similarly, if .php is appended to a file path (like shellcode.php), adding a /. at the end will not alter the file being accessed.
  • This 漏洞 was corrected in PHP 5.3.
  • php://memory and php://temp — Write in memory or in a temporary file (not sure how this can be useful in a 文件包含 attack)
  • ssh2:// — Secure Shell 2
  • ogg:// — Audio streams (Not useful to read arbitrary files)
  • Functions that might be vulnerable: file get contents, readfile, finfo->file, getimagesize, md5 file, sha1 file, 哈希 file, file, parse ini file, copy, file put contents (only target read only with this), stream get contents, fgets, fread, fgetc, fgetcsv, fpassthru, fputs
