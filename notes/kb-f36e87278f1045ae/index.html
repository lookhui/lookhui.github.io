# Web 漏洞验证方法论

# 提炼原则

  • 先判定上下文：输入进入 HTML、属性、JS、SQL、模板、文件系统、URL 还是系统命令。
  • 再判定解析链：浏览器、前端框架、网关、反向代理、后端框架、数据库、中间件各自可能重写输入。
  • 使用最小 payload：从单引号、布尔差异、时间差、DNS/OAST、模板表达式、路径探测等低噪声信号开始。
  • 把绕过拆成变量：编码、大小写、注释、分隔符、协议、重定向、二次触发、缓存、Content-Type。
  • 影响验证要收敛：优先证明读 / 写 / 执行 / 越权中的最小一种，不直接做破坏性操作。
  • 记录失败条件：过滤器表现、WAF 告警、状态码、延迟、回显位置和不可达原因都能转化为知识。

# 关联入口

  • SQL 注入
  • XSS 跨站脚本
  • SSRF 服务端请求伪造
  • SSTI 服务端模板注入
  • 文件上传与文件包含
