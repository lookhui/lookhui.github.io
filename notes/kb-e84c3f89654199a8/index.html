# 核心要点

  • Phase 1: A secure channel is created between two endpoints. This is achieved through the use of a Pre-Shared Key (PSK) or certificates, employing either main mode, which involves three pairs of messages, or aggressive mode.
  • Phase 1.5: Though not mandatory, this phase, known as the Extended 认证 Phase, verifies the identity of the user attempting to connect by requiring a username and 密码.
  • Then, in this case we already have a valid transformation but if you are in the 3rd case, then you need to brute-force a little bit to find a valid transformation:
  • And then brute-force each one using ike-scan (this can take several minutes):
  • You can try the same attack using iker.py.\
  • 2 = HMAC-SHA = SHA1 (in this case). The --trans format is Enc,Enc,Enc, 哈希，Auth,Auth,Auth,DH
  • Packet: IKE SA INIT response contains one or more Vendor ID 载荷
  • WatchGuard format: 32-byte 哈希 followed by base64 that decodes to e.g. VN=12.11.3 BN=719894
  • This is not part of any IKEv2 RFC. Treat it as a vendor quirk for rapid scoping of exposed/vulnerable Fireware OS versions.
  • iker.py also uses ike-scan to bruteforce possible group names. It follows it's own method to find a valid ID based on the output of ike-scan.
  • The first method is to brute-force the group names by searching for the information Dead Peer 检测 DPD of Cisco systems (this info is only replayed by the server if the group name is correct).
  • Replace [VPN USERNAME] and [VPN 密码] with the VPN 认证 凭据.
  • Follow with IKE SA AUTH carrying an IDi that triggers the bug (e.g., an oversized Identification copied into a fixed-size stack buffer before certificate validation).
  • With NX enabled but other mitigations missing (no PIE/canaries), build a ROP 返回导向编程 chain to call mprotect on a stack page and then pivot execution to injected shellcode or to a resident interpreter (e.g., /usr/bin/python3) if no /bin/sh is available.
