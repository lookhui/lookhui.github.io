# 核心要点

  • In order to prevent bypasses Nginx performs path normalization before checking it. However, if the backend server performs a different normalization (removing characters that nginx doesn't remove) it might be possible to 绕过 this defense.
  • Nginx is configured to block access to /admin.php but it's possible to 绕过 this by accessing /admin.php/index.php.
  • This research mentions that it was possible to 绕过 AWS WAF rules applied over HTTP headers by sending a "malformed" header that wasn't properly parsed by AWS but it was by the backend server.
  • For example, sending the following request with a SQL 注入 in the header X-Query:
  • It was possible to 绕过 AWS WAF because it wouldn't understand that the next line is part of the value of the header while the NODEJS server did (this was fixed).
  • This is especially relevant in 利用 chains such as React2Shell, where the malicious server-side object graph can stay unchanged while only the HTTP transport syntax is mutated until the WAF and the origin disagree.
  • Duplicate parameter precedence mismatch: if the WAF uses the last boundary= but the backend uses the first one, the WAF can parse an empty body while the backend parses the attacker-controlled parts.
  • Boundary termination quirks: if the WAF accepts --boundary-- as the final marker but the backend rejects the trailing whitespace, the WAF stops scanning too early and the backend keeps parsing later parts.
