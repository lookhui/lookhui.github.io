# 核心要点

  • DA1 is signed/loaded by BootROM/Preloader. When 下载 Agent 授权 (DAA) is enabled, only signed DA1 should run.
  • DA2 is sent over USB. DA1 receives size, load address, and SHA-256 and hashes the received DA2, comparing it to an expected 哈希 embedded in DA1 (copied into RAM).
  • Weakness: On unpatched loaders, DA1 does not sanitize the DA2 load address/size and keeps the expected 哈希 writable in memory, enabling the host to tamper with the check.
  • First BOOT TO: Enter the DA1→DA2 staging flow (DA1 allocates, prepares DRAM, and exposes the expected - 哈希 buffer in RAM).
  • 哈希 - slot overwrite: Send a small 载荷 that scans DA1 memory for the stored DA2-expected 哈希 and overwrites it with the SHA-256 of the attacker-modified DA2. This leverages the user-controlled load to land the 载荷 where the 哈希 resides.
  • Second BOOT TO + digest: Trigger another BOOT TO with the patched DA2 metadata and send the raw 32-byte digest matching the modified DA2. DA1 recomputes SHA-256 over the received DA2, compares it against the now-patched expected 哈希，and the jump succeeds into attacker code.
  • 载荷 replicates the paid-tool blob that patches the expected - 哈希 buffer inside DA1.
  • DA2 can be any attacker-built image; choosing the load address/size allows arbitrary memory placement with cache invalidation handled by DA.
  • Mitigation: Updated DAs hardcode the DA2 load address to 0x40000000 and ignore the address the host supplies, so writes cannot reach the DA1 哈希 slot (~0x200000 range). The 哈希 remains computed but no longer attacker-writable.
  • Detecting patched DAs: mtkclient/penumbra scan DA1 for patterns indicating the address-hardening; if found, Carbonara is skipped. Old DAs expose writable 哈希 slots (commonly around offsets like 0x22dea4 in V5 DA1) and remain exploitable.
  • Devices where DA2 address/size are unchecked and DA1 keeps the expected 哈希 writable are vulnerable. If a later Preloader/DA enforces address bounds or keeps the 哈希 immutable, Carbonara is mitigated.
  • Enabling DAA and ensuring DA1/Preloader validate BOOT TO parameters (bounds + authenticity of DA2) closes the primitive. Closing only the 哈希 patch without bounding the load still leaves arbitrary write risk.
